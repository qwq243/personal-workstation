# 文件传输（接口位）

这个仓库**不带**任何网盘 / 云盘实现。

为什么：原来那一份建在某个网盘的私有接口上（要靠网页 cookie、还要客户端注入的原生签名函数），
换个版本就失效，还要求使用者把个人账号的登录态交给工具 —— 那是「能跑」和「该跑」的区别。

但「手机 ↔ 电脑传文件」这个需求是真的。所以这里留的是**接口约定**，不是实现：
你接自己的 WebDAV / S3 / rclone / 局域网共享都行。

## 放在哪

```
server/lib/transfer/
  README.md          ← 就是本文件的副本（这一层现在还没有任何 provider）
  <你的 provider>.mjs
```

## 接口约定

一个 provider 是一个 `.mjs` 模块，导出下面这些函数。**全部返回
`{ ok: boolean, error?: string, ... }`**，不要抛异常（边车的路由分发虽然有兜底，
但抛异常只会让页面看到一个没有上下文的 500）。

```js
/**
 * 自检：当前配置能不能用（凭据在不在、端点通不通）。
 * 页面进「文件传输」时先调它，不能就显示引导而不是一堆空数据。
 */
export function status()

/** 列目录。path 是「别名目录」或具体路径，由 provider 自己解释 */
export async function list({ path = '', page = 1 })

/**
 * 起一个上传任务，**立刻返回** { jobId }。
 * 别在一个请求里等完 —— Node 的 requestTimeout 默认 5 分钟，大文件必被掐。
 */
export async function startUpload({ localPath, path, name })

/** 起一个下载任务，同样立刻返回 { jobId } */
export async function startDownload({ path, name, outDir })

/** 查任务状态：{ status: 'running'|'done'|'error', progress?: 0-100, error?, path? } */
export async function jobStatus(jobId)

/** 拿一个可播放 / 可预览的直链（可选实现）。返回的 URL 应当是浏览器能直接用的 */
export async function link({ path, name })
```

约定三条：

1. **任务化**：上传 / 下载都走「起任务 + 轮询」，接口形状与 `server/lib/memo.mjs`
   的转写任务、`server/lib/wiki-queue.mjs` 的入库队列一致 —— 页面侧可以复用同一套轮询写法。
2. **登录态只有一份**：如果你的 provider 需要凭据，放 `server/credentials.json`
   （在 `server/config.mjs` 的 `SECRET_PATHS` 里加一条），不要在模块里另存一份。
3. **别名目录属于使用者**：原来那套把「电脑→手机 / 手机→电脑 / 共享」三个别名写死在代码里，
   那是作者的个人约定。新 provider 请把别名做成配置项，出厂为空。

## 怎么接进来

1. 写 `server/lib/transfer/<你的 provider>.mjs`，导出上面的函数；
2. 在 `server/config.mjs` 的 `DEFAULTS` 里加一节 `transfer: { provider: '', ... }`
   （目录 / 端点留空 = 模块不显示，见「没配 = 不显示」的约定）；
3. 在 `server/index.mjs` 加 `/api/transfer/*` 路由；
4. 前端加一个 `src/features/transfer/module.ts` + 页面，在 `src/features/index.ts` 里
   `registerModule(...)`（三步法见 docs/architecture.md）。
