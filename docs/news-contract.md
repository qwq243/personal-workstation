# 资讯事件卡（`#/news`）的数据规范

**这份文档是这套东西的合同。** 页面、边车、采集器、AI 概括层都按它来；改之前先改这里。
2026-09-28 的口径（一直有效）：**样式最重要，其次就是这份规范**。

---

## 0. 这个页面吃什么

「资讯」页**不做采集**：它只读一个目录下的文件。那个目录由配置项 **`collector.dir`** 指定
（工作站「设置」里填）；**没填就是没配 —— 这个功能不会出现在侧边栏**（内核约定「没配 = 不显示」）。
采集器是**独立进程**：本机计划任务、定时器、手动跑一次都行，只要能产出下面这些文件。

| 文件（相对 `collector.dir`） | 谁写的 | 页面拿它做什么 | 缺了会怎样 |
|---|---|---|---|
| `out/latest.json` | 采集器 | **页面唯一的内容来源**：最新一批的条目 | 页面报「读不到采集结果」 |
| `out/YYYY-MM-DD-HHMM.md` | 采集器 | 「更早的批次」概要 + 简报（文件名必须是这个格式） | 批次那几颗胶囊不出现，其余照常 |
| `timeline/<主题id>.md` | 采集器 | 「关注主题」的时间线（可展开） | 时间线为空 |
| `cases/<id>.md` | 采集器（可选） | 案卷：溯源记录，前端按 md 渲染 | 案卷列表为空 |
| `sources.json` | 采集器 | 页面「后台」列每个源的档位（频率 / 上次抓取） | 后台那一列为空 |
| `state.json` | 采集器 | 每源上次跑的时间、见过的条目数（只读展示） | 时间显示为空 |
| `watch.json` | 采集器 | 关注主题的定义（`timeline/` 的名字与正则） | 关注主题为空 |
| `reports/index.json` + `reports/*.md` | 采集器（可选） | 深度报告（接口读，页面不直接展示） | 报告接口回空列表 |
| `follow.json` | **边车** | 反向通道：把「点过追踪的卡 + 备注」写回来给采集器读（见 §5） | 采集器拿不到反馈 |

### 0.1 最小 `latest.json`

一个能直接点亮页面的最小例子（**没有 `brief` 也能跑**，页面会退回各源条目）：

```jsonc
{
  "generatedAt": 1790580000000,          // 这一批什么时候生成的（毫秒）；页面显示「数据 N 分钟前」
  "brief": { "text": "本批新增 3 条：…" }, // 可选：采集器自己写的简报，AI 总览还没出来时页面用它
  "sources": [
    {
      "id": "hn",                        // 源 id：决定用哪枚平台图标（见 §3），也用来对 sources.json
      "name": "Hacker News",             // 人类可读的来源名（页面上就显示它）
      "via": "direct",                   // 可选：direct / rss / proxy…，只做展示
      "status": "ok",                    // 可选：ok / error / skipped / idle
      "count": 30,                       // 这一轮这个源抓到几条
      "newCount": 2,                     // 其中新条目几条
      "new": [                           // 新条目（有就优先显示）
        {
          "title": "Show HN: 一个周末写完的小工具",
          "url": "https://example.com/a",   // 去重键：同一条被多个源抓到，按 url 合并
          "desc": "一句话摘要（可选，≤200 字；页面会挡掉机械的样板行）",
          "date": "2026-09-30T09:12:00+08:00", // 可选但**强烈建议**：时效闸门靠它（超过 21 天的不进主流程）
          "cat": "tools"                    // 可选：采集器直接标分类，比关键词猜得准（见 §4）
        }
      ],
      "head": [ /* 没有新条目时页面显示这些（让页面不会是空的），结构同上 */ ]
    }
  ]
}
```

**字段的硬要求**

- `title` / `url` 必填：`url` 是去重键，也是点来源图标去的地方；
- `date` 能被 `Date.parse()` 解析就行（ISO 最省事）。**没有日期的条目一律不会被判「过期」**，
  但也没法判新鲜度 → 论坛类源可以不给，公告类源必须给；
- 顶层 `generatedAt` 用一个毫秒时间戳；页面显示的新鲜度按它算。

## 1. 三条不可动摇的口径

1. **返回的是「AI 高度概括的同类事件」，不是原始标题的搬运。**
   原始标题只用来**回指**（点来源图标去原文），不作为页面的正文。
2. **图表的重点只有「来源」**：每一条事件的来源以**平台图标**给出，图标**可点**（去那条原文）。
   主题构成 / 整体情绪分布 / 各源条数这些「对源整体做统计」的东西，**做了也没意义**，不要。
3. **情绪只谈单事件**（这一条本身偏正/中/负），不谈「这一批整体什么情绪」。
4. 采集范围不由人肉维护：**让智能体自己去找、自己扩**（见 §4 的「采集规范」）。

## 2. 事件卡（页面主体，AI 产出）

```jsonc
{
  "title":    "这件事本身（一句中文，不抄原标题）",
  "summary":  "它到底在讲什么 / 为什么值得看 / 跟服务对象有什么关系（2-3 句）",
  "mood":     "pos | neu | neg",                            // 只评价这一条事件本身
  "cat":      "focus | kaoyan | ai | tech | tools | world | other", // 见 §2.4
  "tags":     ["新产品", "教程"],                            // 见 §2.1，用来聚焦
  "sources": [                                              // 这张卡对应的原始条目（**必须能回指**）
    {
      "title": "原始标题（原样，用来跟采集结果对齐）",
      "source": "人类可读的来源名",
      "id":   "源 id（决定用哪枚平台图标，见 §3）",
      "url":  "原文链接（图标点了就去这里）"
    }
  ],
  "at": 1790580000000                                       // 这张卡所属批次的生成时间（毫秒）
}
```

**硬要求**

- `sources` 非空。**没有来源的卡不许出现** —— 「看了等于白看」指的就是没有出处的那种。
- `sources[].title` 必须与采集结果里的标题**逐字一致**：边车靠它对回 `id`/`url`/图标。
- `title` 与 `summary` 是给人看的；`sources[].title` 是给机器对账的。两者别混用。

### 2.1 标签

标签是**给人聚焦用的**，不是分类的替代。固定这组（别自由发挥，否则聚不起来）：

| 标签 | 什么时候打 |
|---|---|
| `新产品` | 新模型 / 新硬件 / 新版本 / 新服务发布 |
| `教程` | 怎么做、经验分享、踩坑复盘 |
| `薅羊毛` | 免费额度、优惠、代充、限时活动 |
| `工具` | 可直接拿来用的工具 / 开源项目 |
| `论文` | 论文、技术报告、顶会 |
| `政策` | 官方规定、监管、通知 |
| `招聘` | 实习 / 校招 / 就业 |
| `讨论` | 论坛里的观点与争论（没有结论但有信息量） |

页面上标签**可点=筛选**。

### 2.2 热度（`heat`）

每条给一个热度信号，**没有就不显示**（别编）：
`heat: { n: 342, unit: "评论" }`（论坛帖子用评论数）/ `{ n: 128, unit: "points" }`。
数据来自各站自己的公开接口（V2EX `replies`、HN `points`+`descendants`、Discourse `posts_count`）。

### 2.3 追踪（`tracked`）

卡片上的「追踪」= 让下一轮 AI **在原来那张卡上继续补齐**，而不是重新生成一张。
- 在 `prefs.tracked` 里留 `{title, at}`（边车 `<dataDir>/news-prefs/`）；
- 概括时把这批 tracked 卡的**现有标题与摘要**一起喂进去，并明确要求：相关的新条目要**并进同一张卡**（标题原样返回），摘要写得更全；
- 页面给 tracked 卡一个绿色「已追踪」标记；同时这份清单会导出给采集器（见 §5 的 `follow.json`）。

### 2.4 分类（`cat`）—— 词表固定，判据可配

分类只有这七个，中文标签一一对应：

| cat | 中文 | 什么时候用 |
|---|---|---|
| `focus` | 与我相关 | **配置驱动**：条目命中 `news.focusKeywords`（字符串数组）里的任一个关键词 |
| `kaoyan` | 考研 | 研招 / 招生 / 报名 / 复试 / 调剂 / 分数线 / 四六级这类考试节点 |
| `ai` | AI | 模型 / 智能体 / 大模型 / 算力 |
| `tech` | 科技 | 芯片 / 系统 / 平台 / 安全 |
| `tools` | 工具 | 开源项目 / 自托管 / 命令行 / 能上手的东西 |
| `world` | 世界 | 宏观 / 地缘 / 政策 |
| `other` | 其他 | 都不中的 |

判据**从上到下第一个命中说了算**（实现在 `server/lib/news-board.mjs` 的 `classify()`）：

1. **采集器标的 `cat`**（条目级优先于源级）—— 最权威：源清单是人工挑的，标了就是标了；
2. **`news.focusKeywords` 命中** → `focus`。这是「与我相关」的入口，配置驱动，代码里不写死任何机构名；
3. 公开平台源的**内置默认分类**（HN / V2EX / 论坛 / 仓库趋势这类）；
4. 关键词规则（考研 / AI / 世界 / 工具 / 科技），都不中就是 `other`。

页签只有 5 个：**与我相关（= focus + kaoyan）/ AI / 科技（= tech + tools）/ 世界 / 全部**。
`other` 只在「全部」里出现 —— 分类不合并的话，页签会多到没人点。

## 3. 批次（「更早的批次」那排胶囊）

```jsonc
{
  "at": 1790580000000,        // 这一批什么时候概括的
  "batchId": "1790570000000", // 概括的是哪一批（取那批最新条目的时间戳）
  "summary": "这一段里发生了什么：一两句，给批次胶囊用",
  "cards": [ /* §2 的数组 */ ],
  "model": "（实际用的模型名，写不写都行）"
}
```

页面顶部只显示**最新一批的 `summary`**；更早的批次进胶囊条，点一下就停在那一批。
批次 md（`out/*.md`）里那行 `## 简报` 是**采集器自己写的**，页面在 AI 总览还没出来时用它兜底 ——
所以采集器最好每批都写一句，别留空。

## 4. 来源图标

一枚源一枚图标（`src/features/news/icons/`，`sourceIcons.ts` 与两个页面各登记一份）。
**新增源要在那三处各补一条**，否则退化成通用 RSS 图标 —— 能点但认不出是哪家。

| 源 id | 图标 |
|---|---|
| `chsi-yz`（研招网这类官方源） | `ChsiIcon` |
| `x-*` | `XIcon` |
| `linuxdo-*` | `LinuxDoIcon` |
| `v2ex` | `V2exIcon` |
| `hn` | `HnIcon` |
| `github-hot` | `GithubIcon` |
| `sspai` | `SspaiIcon` |
| `wx-*` | `WeixinIcon` |
| `bili-*`（B 站这类视频渠道） | `BiliIcon` |
| 别的（`world-*`、`tech-*`…） | 通用 `RssIcon`（有自己的图标就换） |

查表是**先精确匹配源 id、再按平台前缀兜底**（`bili-某频道` 找不到 `bili-某频道` 这条就用 `bili` 这一条），
所以「一个平台挂一批账号」的源只要在那个平台键上登记一次就够 —— `x-*` / `wx-*` / `linuxdo-*` 里的
逐条登记是可选的（想让某个账号单独换一枚图标时才写）。

## 5. 采集规范（采集器那一侧的活）

采集器读两份文件：

- **`sources.json`**：抓什么。字段
  `id / name / type / url / everyMinutes / limit / titleExclude / cat / disabled`。
  题目里的 `cat` 是**源级默认分类**（见 §2.4 判据 1），条目还可以各自覆盖它。
- **`watch.json`**：关注什么。字段 `id / name / note / match(正则)`；命中的条目进 `timeline/<id>.md`。

**这两份文件由采集器（或它的智能体）维护**：加源的动作 = 改这两份文件 + 重跑，不需要改边车代码。
仓库里带了一个**最小示例采集器** `scripts/collector-skeleton.mjs`（零依赖、只抓公开 RSS），
跑一次就能把这一页点亮：

```bash
node scripts/collector-skeleton.mjs ./collector-out
# 然后把打印出来的目录填进工作站「设置 → 采集器目录」
```

### 5.1 反馈的两条路

1. **采集器 → 页面**：`out/`、`timeline/`、`cases/`、`sources.json`、`state.json`、`watch.json`（§0 的表）；
2. **页面 → 采集器**：边车把「点过追踪的卡 + 写下的备注」导出成 `<collector.dir>/follow.json`：

```jsonc
{
  "at": 1790580000000,
  "tracked": [{ "title": "…", "summary": "…", "note": "…", "at": 1790570000000 }],
  "notes":   [{ "at": 1790570000000, "title": "…", "note": "以后别给我 GitHub 仓库推荐", "kind": "blacklist", "applied": false }],
  "learned": { "kws": [{ "w": "开源模型", "v": 0.3, "dir": "up" }] }   // 👍/👎 学出来的偏好
}
```

采集器读它就知道「哪几张卡要补厚」「哪条规则要真的生效」。**点一下就会更新**（边车节流 20 秒），
不是定时任务 —— 反馈的手感比实时性重要。

## 6. 边车接口

| 接口 | 用途 |
|---|---|
| `GET /api/news/dashboard?force=1` | 页面唯一的数据入口：`brief` / `ai`(批次+卡+状态) / `items` / `tasks` / `learned` / `suggestions` |
| `POST /api/news/digest` | 手动跑一批 AI 概括（「现在概括」） |
| `POST /api/news/feedback` | 👍/👎/备注 |
| `POST /api/news/apply` | 一键采纳某条备注 |
| `POST /api/news/track` | 追踪 / 取消追踪一张卡 |
| `GET /api/news/feed` | 最新一批的原始条目（排障与别的客户端用） |
| `GET /api/news/batches?limit=8` | 历史批次（`out/*.md` 解析出来的） |
| `GET /api/news/timeline[?id=]` | 关注时间线（不传 id = 索引） |
| `GET /api/news/case[?id=]` | 案卷原文 |
| `GET /api/news/reports` / `GET /api/news/report?file=` | 深度报告（可选产物） |
| `GET /api/news/follow-status` / `POST /api/news/follow-push` | 导出给采集器的那份 `follow.json` 的状态 / 手动导一次 |

## 7. 页面版式

```
① AI 大总结        ← 上一批的一段话，最重要的一块，放最上面
② 时段筛选 + 更早的批次  ← 选区间看那一批的概要；更早的批次自动轮播，点一下就停
③ 事件卡列表        ← **页面主体**：AI 概括卡 + 来源图标（可点）+ 单事件情绪 + 👍👎✎
④ 后台（收起）      ← 采集器档位 / 关注时间线，默认不展开
⑤ 原始条目（抽屉）  ← 原始标题只在这里，给回指与对账用
```

**不要**：主题构成环形图、信息来源条形图、整体情绪分布条、以原始标题为主的事件流。
