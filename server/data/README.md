# server/data —— 本机数据目录（这里只有示例）

这个目录放**边车自己的数据**：看板、规划台、词单、知识库索引、上传的音频、进程守护审计…
默认位置由 `server/config.json` 的 `dataDir` 决定（不填 = 就是这里）。

## 你现在看到的是示例，不是谁的数据

仓库里**只提交了下面这几个文件**，它们是「空结构 + 一份示例」：

| 文件 | 是什么 | 首次启动会怎样 |
|---|---|---|
| `dashboard.json` | 每日看板（计划 / 记录 / 心情 / 复盘） | 空结构；你在页面上写第一条计划时就变成你的了 |
| `plan.json` | 规划台（关键日期 / 项目 / 备考清单） | 空结构；在「规划台」页里自己加 |
| `school-calendar.json` | 校历（上不上课 / 第几教学周 / 放假 / 调休） | **示例数据**，`school` 写的是「示例大学」——换成你学校的，格式见 `docs/校历格式.md` |
| `vocab/lists.json` | 词单 | 空结构；出厂示例词单由前端内置，进「英语学习」能看到 |
| `vocab/progress.json` | 词单学情（掌握度 / 练习历史 / 目标画像） | 空结构 |

**其余一切都由程序在运行时生成，不进版本库**（`.gitignore` 里整个 `server/data/*` 被忽略，
只有上面这几个用 `!` 规则放行）。所以那些「个人数据」是**生成出来的，不是随仓库分发的**：
看板记录、词单进度、口述音频、知识库向量、AI 总结存档、进程守护审计、每日快照 `.bak` / `backups/`…

## 想看「有数据长什么样」

`server/data/` 下的 `dashboard.json` / `plan.json` 出厂是空的（那是你自己的日志，不该预填别人的）。
想快速看一份填满的界面，跑一次这个脚本：

```bash
node scripts/seed-demo-data.mjs          # 写入示例数据（日期按「今天」推算）
node scripts/seed-demo-data.mjs --reset  # 清回空结构
```

它只写 `dashboard.json` / `plan.json`，并且**非空时会拒绝覆盖**（要覆盖加 `--force`）。

## 想全部重来

```bash
# 停掉边车，然后把数据目录清成出厂样子（三个文件 + vocab 两份）
rm -rf server/data/*            # Windows: rd /s /q server\data && mkdir server\data
# 再按上面的表格把那 5 个文件建回来，或者直接让程序生成空结构
```

删掉某个文件也没关系：`server/lib/jsonstore.mjs` 在文件不存在时用**空结构**，读坏了会依次
回退 `.bak` → 每日快照，并把坏文件另存 `.corrupt-<时间>` 留证（不会静默当空数据）。

## 备份

整目录拷走就是全量备份 —— 纯文件，没有数据库要 dump。
`backups/` 里是各模块的每日快照（保留最近若干份），由程序自动维护，不用手动管。
